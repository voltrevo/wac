# wac-L5 — the rung that is handed its language

Every rung below this one is a language we chose, with a feature set we bounded. **wac-L5 is wac**,
and it has to accept whatever `packages/wacc/src` happens to be written in. That is the whole
difficulty, and it is why the ratio breaks here: L2 to L4 each cost about 2.2× the rung below, and
L5 will not.

The measured target, from wacc's own 34,494 lines:

| what it uses | count | where it lands |
|---|---:|---|
| `for` loops | 1,013 | **stage 1** — desugars to `while` |
| casts `as` / `as!` | 969 | stage 2 |
| `i64`/`u32`/`u8`… | 910 | stage 2 — a numeric lattice |
| string concatenation | 659 | stage 3 |
| ternary | 450 | **stage 1** |
| `const` | 331 | **stage 1** — parsed and ignored; L5 has no checker |
| generic instantiations | 283 | **stage 4** — monomorphisation |
| `match` | 254 | stage 2 |
| `trap` | 90 | **stage 1** |
| imports | 44 | stage 3 |

## Stage 2, which also exists

**The type system**, and it is where wac's own shape arrives:

- `struct Name { T f; … methods }`, constructed as `Name(a, b)`, with `const this` receivers;
- `enum Name { A(T v), B, … methods }` — variants comma-separated, methods after them;
- **`match` as a statement *and* as an expression**, which is one token apart: an arm's body ends in
  `,` in the expression form and `;` in the statement form. `_` binds nothing;
- arrays: `T[]`, `T[n]()`, the literal `T[](a, b, c)`, `xs[i]`, `xs.len()`;
- `u8[]`, a byte string;
- reference globals, and `null`;
- `x!`, which is a no-op on a value that is already nullable;
- named arguments — `fill: v` — read and discarded, because the callee's signature already fixes
  what they mean.

**A variant and a method are told apart by a type-then-name-then-`(` lookahead**, not by what
follows the name. `None` before a `bool isSome(` is a name followed by a name, and so is `bool
isSome` — the last variant before the first method reads as that method's return type otherwise.

## Stage 3, in part: the numeric lattice

wasm has **two** integer value types. wac has **eight names** for them, differing in width and in
signedness, and those two facts decide which instruction every operator emits:

| wac | held in | `/` emits | `>` emits |
|---|---|---|---|
| `i32`, `i8`, `i16`, `bool` | i32 | `i32.div_s` | `i32.gt_s` |
| `u32`, `u8`, `u16` | i32 | `i32.div_u` | `i32.gt_u` |
| `i64` | i64 | `i64.div_s` | `i64.gt_s` |
| `u64` | i64 | `i64.div_u` | `i64.gt_u` |

Nothing else in the compiler can tell `u32 / u32` from `i32 / i32`; both are one wasm type and the
difference is entirely in the mnemonic.

**`i8` and `i16` are storage types**, legal only as an array element or a struct field, and reading
one **widens** — signed or unsigned according to the wac type, which is the whole reason wasm has
both `array.get_s` and `array.get_u`.

**`x as T`** widens with `i64.extend_i32_s`/`_u`, narrows with `i32.wrap_i64`, and is otherwise a
reinterpretation: `i32` and `u32` are one wasm type. **`as!` is a *checked* cast in wac** and traps
on overflow; this emits the same conversion and does not check, which is a gap.

## Stage 3, in part: strings

**`string` is a GC array of bytes** — the same array type a `u8[]` is, so `.len()` and `[i]` work on
it with no second implementation, and a literal and a built string are one kind of value.

A literal lives in **linear memory** as a length and its bytes, which is how every rung below writes
one. An emitted `$__strlit` lifts it into the array; `+` calls an emitted `$__concat`. Both are
written out only if something used them, because a program with no strings should not carry them.

wac's `string` is **immutable** and this one is not, which is a gap that nothing here can observe —
and `"a" + n` for a number `n` is not supported, because wac converts explicitly and so should this.

## Stage 4: generics, by rewinding

**A generic declaration is not compiled where it is written.** Its token index is recorded and its
body is re-read once per instantiation, with the letters bound:

    struct Box<T> { T v; T get(const this) { return this.v; } }

    Box<i32> a = Box(7);      // $s9  with a method $Box_9_get
    Box<bool> b = Box(true);  // $s12 with a method $Box_12_get

That is cheap here for a reason peculiar to this compiler: **the parser's entire state is one
integer into the token array**, so "read this declaration again, in another world" is an assignment.
It is the third time having no syntax tree has paid for itself, after the `for` loop's step and the
`match` arms.

**Expanded where it is created**, not in a later pass — an instantiation is first named inside a
function body, long after any pass over the declarations could have run. The entry is marked
expanded *before* its body is read, so `Vec<T>` holding a `Vec<T>` finds the entry already there
rather than making a second one, and that is what terminates it.

**The mangled name carries the type index.** `$Box_9_get` and `$Box_12_get`, because a template's
name is shared by every instantiation of it and cannot tell two apart on its own.

**The slot supplies the type argument**: `Box<i32> a = Box(7);` writes the arguments once, and the
second `Box` reads its instantiation from the declaration it is initialising. Inside a template's own
body a bare `Vec(…)` means the instantiation being expanded.

**`>>` closes two argument lists.** The lexer packs it into a shift, which is right everywhere else,
so the token is rewritten in place as the *second* `>` and left where it is — the next closer finds
a plain one. `Vec<Vec<i32>>` works.

## Stage 3, in part: imports

wac compiles a whole program into **one** wasm module, so an import is a file to *include* rather
than a boundary to cross — and resolving one is path arithmetic and a file read, neither of which a
wac-L4 program can do. The driver flattens the graph, which is where `files.wac` does it in the real
compiler: depth first, post-order so a file follows everything it imports, and visited once so a
diamond does not duplicate a declaration.

The compiler skips `import` lines, which is all it has to do once the text has arrived in one piece.

## Stage 1, which came first

**The shape of the language, over the i32 subset.** Everything that is only syntax:

- `export`, `//` and `/** … */` comments, doc comments before any declaration;
- functions, `const this` receivers, globals;
- `return`, `if`/`else`/`else if`, `while`, `for`, blocks, declarations with shadowing, `trap`;
- the full precedence chain — ternary, `||`, `&&`, `|`, `^`, `&`, equality, comparison, shifts,
  additive, multiplicative, unary `- ! ~`;
- `++`, `--`, `+=`, `-=`, `*=`, `/=`;
- `true` and `false`, which are `i32` here;
- types read in full — `T`, `T[]`, `T?` — and emitted as `i32`, so the parser is already the shape
  it needs to be and only the emission is narrow.

**`&&` and `||` short-circuit**, which is not decoration: a guard followed by a dereference is the
usual shape in wacc's source, and an `i32.and` would evaluate both sides.

## What stages 1 and 2 get wrong, deliberately

- **`T?` is the same wasm type as `T`.** Every reference here is already nullable; a nullable
  *primitive* is boxed in wac and is not, which is a real gap.
- **`T[n](fill: v)` evaluates the fill and drops it.** `array.new_default` zeroes, and carrying a
  value into it is not done yet.
- **a ternary answers `i32`.** Its block type is written before the branches are parsed, so a
  reference-typed ternary is refused by the engine. A `match` *expression* had the same problem and
  is fixed — its arms go to a scratch buffer and the header is written in front of them — and the
  ternary should be done the same way.
- **a global's initialiser is not run.** Globals emit as zero and the program is expected to set
  them, because a wac initialiser can be an arbitrary expression and wasm's cannot.
- **string escapes other than `\n \t \r \0` pass through unchanged**, which is wrong in a way the
  assembler will not catch.
- **no `<<=` or `>>=`.** Nothing in `wacc/src` uses them; the lexer would mis-read them as `<<` and
  `=`, so this is a real gap rather than a choice.

## How it is compiled

One pass, no syntax tree, as in every rung since L3 — with one addition the `for` loop forces.

**A `for`'s step is read before the body and emitted after it**, so the parser rewinds: it records
the token index of the step, skips to `)`, parses the body, then sets the cursor back, emits the
step, and restores. That costs nothing here because the parser's entire state is one integer into
the token array — which is a property of having no tree, and the first time it has paid for itself.

The tables are **GC arrays**, not fixed addresses. That is the first compiler on this ladder for
which that is true, and it is what wac-L4 was built to make possible.
